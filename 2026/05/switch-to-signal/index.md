# Mobile instant messaging still sucks, so I (kinda) switched to Signal
If you know me and have read past articles on this Blog, you may know well that I really hate how the mobile IM services market is underwhelming at best and [dangerous](/2022/11/whatsapp-sucks/) at worst. The issue of WhatsApp being the main Instant Messaging app for mobile devices in many countries (including Italy) still remains, and I also haven't found a way to completely quit and delete my account for good. But even the competition hasn't been quite good in the last years, and when it comes to the criterias I used to and still want in a mobile IM service none of the alternatives have ever been good enough.

For when it comes to those criterias, well...

## ...what I want from a mobile IM service/protocol
- **It has to be free and open:** every single device should, at least possibly, manage to use this service. If it can't be ported to Sailfish OS, MeeGo Harmattan, Windows Phone or other less-popular mobile operating systems then it failed at its task. WhatsApp is the perfect example of sucking on respecting this criteria: support limited to the current duopoly of mobile OSes (Android and iOS), comepletely closed-source, doesn't officialy support the use of third-party clients and it's owned by Meta of all companies. Threema is actually pretty good on the privacy side, but it's paid and the server and API are completely closed source which makes it a big no-no in my "WhatsApp alternatives" list. While XMPP, being an open and really standardized protocol, is for now still the best on this regard.
- **It has to be private:** and no, being end-to-end encrypted is not enough: it shouldn't collect more personal data than it should, it shouldn't have any backdoors from which anyone can retrieve chat contents and it shouldn't be owned by companies known for not respecting users' privacy. It's not hard to see where this issue presents for WhatsApp, it's owned by one of the biggest and most known companies for heavy tracking of personal data.
- **It should be decentralized:** the user shouldn't depend on a single server or provider, being able to use multiple providers or even host your own server makes an IM service good at not keeping users locked-in to a certain big tech company, a thing that centralized messaging providers unfortunately suffer from.
- **It should be fairly easy to use:** not everyone is an IT geek, a good mobile IM service shouldn't give its normal users any headache. Unfortunately messaging services that are decentralized, given their nature, have a disadvantage on satisfying this requirement as, aside from having to choose a provider which isn't really a problem, understanding how the clients work is way harder and the use of username + domains associations can make understanding which one every contact has can be hard, especially if you're already used to using phone numbers.
- **It should be interoperable/have some type of fallback:** and last of all, given that not everyone has the want or will to subscribe to a whole new IM service, being able to use a fallback, mainly a standard like MLS was supposed to be and SMS as a last resort (while still having to recognize the caveats and security risks involved in using it) as it's what literally every single device with an active phone carrier plan.

Optionally I'd also really want the client have an adequate UX and at least decent aesthetics in the UI.

## How it's been in the last years
I have mainly used RCS for the longest time, even given [my past criticisms](/2023/06/rcs-now-sucks/) it was what I was using for a while and the fact that it was usually enabled by default for every Android device with an RCS messaging client (almost always Google Messages) made it way easier to adopt, and the SMS fallback allowed me to send text messages even to people that didn't have RCS enabled or supported on their device.  
Unfortunately, given all the enshittification that Google made and that Jibe (Google's RCS implementation) became one of their many monopolies, and given how I'm slowly trying to quit Google (for the most part at least, hardware is currently excluded), I've made sure to also consider the other decentralized and/or private options that I could finally replace Google Messages with.

### Telegram: really good on features, but...
It has been one of my most used IM apps, especially for online communities, I always loved the fact that it was full of modern features that really made (and sometimes still make) it really forward-thinking. It's one of the few messaging services that had/have full cloud syncronization, good group and channel amministration with fine-grained permission management, a bot system that doesn't suck, chat folders, personal details visibility management and many more.  
Unfortunately I still can't really recommend it (especially for private chats) because of the reasons I've mentioned on my ["Telegram sucks too" article](/2024/08/telegram-sucks-too/).

### Matrix + XMPP, the peak of decentralized messaging
XMPP remained for a lot of time one of my favorites, it has been in the market for quite some years and, while it has matured a lot, being an old protocol means that it can also be quite complicated. Unlike Matrix which completely works with HTTP(S) and can be set up under a reverse proxy, XMPP requires exposing a couple more TCP ports + a whole web server if you want good file sharing, setup can be a bit more complicated if you opt for self-hosting and it can miss features that nowadays we take for granted like message reactions or sticker packs.  
Matrix is more modern and except for its easier hosting setup (except requiring a bit more effort to make federation work) has also more features built-in like good file sharing and encrypted message sync. Unfortunately Matrix has a couple of throwbacks that I don't really like: mainly the fact that contacts don't really exist and you can't, for example, change to a display name different from the global one of another contact on your chat list. I also have a big issue with Element X's notification system on Android, they're setup to be in the "silenced notifications" category and even if you move them out, they still don't count as "chats" in Android's notification system.

### Session, a good concept with "mehh" execution
Session is actually a good compromise between decentralization and ease of use, it's mainly based on an open-source peer-to-peer "blockchain" (yeeah that term 🤮) network composed of nodes. It's also one of the few anonymous no-ID messaging solution which means no phone number or "address" is used, users are identified with an ID that unfortunately has to be shared with your recipient and isn't really easy to remember. I've used it one time in the past and, while I have downloaded it again, there wasn't really anyone who had it and I could chat with. It will also probably shut down on the 8th of July (2026-07-08) due to "insufficient funding". There are also some crypto features like SESHs (Session Tokens) which don't really make it seem that trustable.  
There's always **SimpleX** which is also another no-ID decentralized alternative that works pretty much in the same way without it shutting down or having any crypto bullsh*t.

## My (kinda) final choice
While it has a lot off issues and actually doesn't meet the criteria of decentralization, I'm now planning to use **Signal** as my main IM app for private chats. There are a couple of reasons to this: mainly because it's the perfect compromise between privacy+security and ease of use, the use of phone numbers (while debatable on how good it is) makes contact finding easier and makes it simpler for normal people. While using Signal means keeping some of the caveats of using WhatsApp the architecture is comepletely open-source making it easy to port clients to other devices or potentially spinning up a different server if Signal's infrastructure ever gets shutdown, it's owned by a non-profit that build Signal to have no ads, no tracking and relies on user donations to keep the infrastructure active. While it still has issues coming from its centralized nature I still think it's one of the best IM services we can now use.

### What I'd add to Signal to make it better
Before starting I want to say that these are not enhancements that I expect to happen and I recognize that some of them can be hard to realize or go against Signal's whole philosophy, this is just a list of improvements I would really love to see on Signal.

- First of all, **official support for standalone use on even more mobile OSs**, while it can be hard to make such clients I genuinely hope something like this could happen to cover up even more mobile operating systems that go beyond the Android+iOS duopoly.  
- Even more importantly, **interoperability**, if Signal added support to bridging with more IM services it could actually help with the not-so-large userbase. I used to want an optional **SMS fallback** which Signal actually [removed from the Android client](https://signal.org/blog/sms-removal-android/) a while ago, but I now understand the reasons of the removal and recognize it would create confusion and not be appropriate for such client, I'd rather have a separate client for SMS messaging.

## Conclusion
I still struggle with finding the right solution for mobile instant messaging and still think the scene sucks. I have yet to know it I can and should ultimate the switch to Signal but the situation for now is that I use it as my current top-choice for the time being while I still use SimpleX, Matrix, XMPP and RCS/SMS as fallback.
